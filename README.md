# بک‌اند خودروچاره

Node.js 22 + Express 5، PostgreSQL 16/PostGIS، Prisma 6، Redis، BullMQ و Socket.IO. دو نقش مستقل `CUSTOMER` و `DRIVER` با session تصادفی، رمز عبور scrypt و کنترل دسترسی سمت سرور پیاده‌سازی شده‌اند. ساخت یا نصب دیتابیس روی کامپیوتر توسعه لازم نیست.

## نصب روی سرور

پیش‌نیاز: Docker Engine و Docker Compose نسخه 2.24.4 یا جدیدتر. پوشه کامل `khodrochare-backend` را به سرور منتقل کنید. فایل `.env` تولیدشده شامل رمزهای تصادفی است و داخل Git یا ایمیج Docker قرار نمی‌گیرد. اگر آن را منتقل نمی‌کنید، روی سرور بسازید:

```sh
cd khodrochare-backend
# فقط در صورت نبودن .env؛ Node.js محلی لازم نیست
docker run --rm -v "$PWD:/app" -w /app node:22-bookworm-slim node scripts/setup-env.js
```

مقادیر زیر را در `.env` متناسب با پروژه تنظیم کنید:

- `CORS_ORIGINS`: آدرس کامل دو اپ، با کاما؛ بدون `/` انتهایی.
- `API_DOMAIN`: دامنه بک‌اند؛ رکورد DNS آن باید به سرور اشاره کند.
- تعرفه حمل از جدول تصویر در `src/pricing.js` خوانده می‌شود. `SESSION_DAYS=90` را برای ماندگاری ورود تنظیم کنید. جزئیات در [راهنمای تعرفه و نشست](docs/TARIFFS-AND-SESSIONS.md).
- `DISTANCE_MODE=road` و `OSRM_URL`: سرویس مسیریابی جاده‌ای. آدرس عمومی پیش‌فرض برای شروع است؛ برای بهره‌برداری سرویس قابل اتکا با پوشش ایران وارد کنید. خطای مسیریابی پاسخ 503 می‌دهد و درخواست با مبلغ تخمینی پنهانی ثبت نمی‌شود.
- `TRUST_PROXY=1`: هنگام استفاده از Caddy ارائه‌شده. دسترسی مستقیم به پورت API باید همچنان روی loopback بماند.

اجرای همراه HTTPS خودکار و پشتیبانی WebSocket، با باز بودن پورت‌های 80 و 443:

```sh
docker compose -f compose.yaml -f compose.edge.yaml up -d --build
docker compose ps
docker compose logs --tail=100 api
curl https://YOUR_API_DOMAIN/health/ready
```

در صورت داشتن reverse proxy موجود:

```sh
docker compose up -d --build
curl http://127.0.0.1:4000/health/ready
```

به‌صورت پیش‌فرض فقط API روی `127.0.0.1:4000` منتشر می‌شود؛ PostgreSQL و Redis پورت عمومی ندارند. دیتابیس، افزونه PostGIS، جداول، indexها و migration در اولین اجرا خودکار ساخته می‌شوند. سرویس API پس از سالم شدن دیتابیس و Redis اجرا می‌شود. مدارک، دیتابیس و Redis روی volume پایدارند. قبل از ارتقا از دیتابیس و volume مدارک بک‌آپ بگیرید؛ `docker compose down -v` داده‌ها را حذف می‌کند.

## رفتار فعلی

- ثبت‌نام مشتری: نام کامل، شماره موبایل ایران، رمز حداقل ۸ کاراکتر و کد ملی معتبر اجباری؛ خودروها، مدارک خودرو و مدرک هویت اختیاری.
- ثبت‌نام امدادگر: همان اطلاعات به‌علاوه پلاک، نوع خودرو، حداقل یک خدمت و تصویر مدرک هویت اجباری.
- شماره تماس و کد ملی در هر نقش یکتا هستند؛ یک فرد می‌تواند در هر دو نقش حساب جدا داشته باشد. ورود با شماره و رمز است؛ OTP و بررسی انسانی اعتبار مدارک در این فاز وجود ندارد.
- درخواست‌ها توسط مشتری ثبت و توسط امدادگر دارای خدمت مرتبط پذیرفته می‌شوند. ثبت‌نام امدادگر به‌خودی‌خود مجوز اداری یا تأیید هویت انسانی محسوب نمی‌شود.
- دو route مستقل برای حمل و تعمیر وجود دارد. سه خدمت دیگر برای پروفایل امدادگر ذخیره می‌شوند و هنوز ماژول درخواست ندارند.
- مبلغ حمل بر اساس گروه خودرو، نیسان/کفی، مسافت و شرایط ویژه مطابق تصویر محاسبه می‌شود. موارد توافقی مبلغ قطعی ندارند. ورودی تعمیر برای همه خودروها ۸۰۰٬۰۰۰ تومان و هزینه قطعات پس از بررسی جداست. [تعرفه کامل](docs/TARIFFS-AND-SESSIONS.md).
- `road`: فاصله مسیر خودرو از OSRM، با کش ۲۴ ساعته Redis. `geodesic`: فاصله مستقیم روی زمین از PostGIS؛ فاصله جاده‌ای نیست. روش محاسبه در پاسخ و دیتابیس ثبت می‌شود.
- فاصله امدادگر تا مبدا فعلاً مستقیم و با `ST_Distance(geography)` است. GPS فقط پس از پذیرش برای طرفین همان درخواست قابل دریافت است. آخرین GPS در دیتابیس ذخیره می‌شود، تاریخچه مسیر در این فاز نداریم.
- GPS قدیمی‌تر از ۱۲۰ ثانیه یا بیش از ۳۰ ثانیه در آینده رد می‌شود؛ بسته‌های خارج از ترتیب جای موقعیت جدید را نمی‌گیرند. موقعیت منقضی‌شده با `stale: true` و بدون مختصات برمی‌گردد.
- هر امدادگر فقط یک مأموریت فعال دارد. پذیرش هم‌زمان با قفل ردیف، update شرطی و index یکتای دیتابیس محافظت می‌شود.
- رویدادهای تغییر درخواست با outbox دیتابیس و BullMQ پردازش می‌شوند. تحویل رویداد حداقل یک‌بار است؛ کلاینت باید تکرار را بر اساس `id` و `updatedAt` تحمل کند و بعد از reconnect با REST همگام شود.
- این استقرار برای **یک instance از API** طراحی شده؛ قبل از اجرای چند replica باید adapter مشترک Socket.IO اضافه شود.

راهنمای کامل endpointها، نمونه payloadها و اتصال زنده: [docs/API.md](docs/API.md).

## تست

```sh
npm ci
npm test
npm run prisma:validate
npm run prisma:generate
npm audit
```

تست یکپارچه واقعی بدون ساخت دیتابیس محلی، در پروژه و volumeهای جدا:

```sh
docker compose -p khodrochare-test -f compose.yaml -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from api
# فقط پاک‌سازی داده‌های همین تست
docker compose -p khodrochare-test -f compose.yaml -f compose.test.yaml down -v
```

تست یکپارچه به دیتابیس با نام `khodrochare_test` و `NODE_ENV=test` محدود شده و سناریوی ثبت‌نام، سند، ورود، جداسازی نقش‌ها، ثبت حمل و تعمیر، محاسبه PostGIS و قیمت، رقابت دو امدادگر برای پذیرش، دریافت GPS توسط هر دو طرف و خروج را پوشش می‌دهد. برای تکرار آن volumeهای پروژه تست را پاک کنید.

وضعیت اعتبارسنجی همین محیط در [docs/VALIDATION.md](docs/VALIDATION.md) ثبت می‌شود. اتصال دو اپ و امکانات آدرس، کاتالوگ و پرداخت در نسخه‌های بعدی همین پوشه تکمیل شده است. [راهنمای استقرار و بررسی واریز](docs/ADDRESSES-CATALOG-PAYMENTS.md).


نسخه پنل مشاهده‌ای، پایش GPS، نقشه حمل، پروفایل و مراحل عملیات امداد: [راهنمای نسخه جدید](docs/MONITORING-AND-APP-UPDATE.md).
