# جمعه‌بازار: دریافت فقط از ترب

نسخه ۱۸ نوامبر ۲۰۲۶، جایگزین تمام اتصال‌های چندمنبعی قبلی است. آداپترهای دیوار، دیجی‌کالا، WooCommerce، JSON feed و JSON-LD عمومی از جریان اجرایی حذف شده‌اند. جست‌وجوی خودکار API ترب نیز کنار گذاشته شده است. داده‌های تاریخی و مالی قبلی حذف نمی‌شوند؛ منابع قدیمی غیرفعال و اجراهای قدیمی لغو می‌شوند.

## روش دریافت

۱. در پنل ادمین `/market`، بخش «لینک‌های ورودی ترب»، یک لینک دسته با مسیر `/browse/` ثبت کنید. لینک نمونه باتری کاربر، هنگام اولین شروع Worker به‌صورت خودکار اضافه می‌شود؛ تغییر یا غیرفعال‌سازی آن در پنل حفظ می‌شود.

۲. صف `torob-browse-v2` با Puppeteer و Chromium صفحه دسته را باز می‌کند، لینک‌های `/p/UUID/` را در هر مرحله جمع می‌کند و به‌تدریج اسکرول می‌کند. لینک‌ها بر اساس UUID یکتا می‌شوند و همان زمان در دیتابیس ثبت می‌شوند؛ لینک یک محصول با دو slug یا پارامتر رهگیری، دوباره شمرده نمی‌شود.

۳. بعد از مرحله جمع‌آوری، صف `torob-product-v2` به صفحات محصول درخواست HTTP می‌زند. JSON-LD محصول و اطلاعات ساخت‌یافته `__NEXT_DATA__` خوانده می‌شوند؛ متن و اسکریپت‌های HTML ارسالی به‌عنوان دستور اجرایی ارزیابی نمی‌شوند.

۴. نام، برند قطعه، تصاویر، توضیحات، مشخصات فنی، قیمت‌های کمینه/بیشینه، موجودی اعلامی، پیشنهادهای فروشندگان و اعتبار قیمت ذخیره می‌شوند. قیمت ریالی فقط با واحد صریح IRR به تومان تبدیل می‌شود. قیمت یا موجودی نامعلوم ساخته نمی‌شود.

۵. مسیر دسته‌بندی از Breadcrumb خود ترب و زیرشاخه لوازم یدکی ۲۹۳ گرفته می‌شود. کالاهای خارج از این شاخه منتشر نمی‌شوند. برندهای قطعات از خود محصول وارد می‌شوند؛ برند خودرو و برند سازنده قطعه با هم یکی نیستند.

## اجرا و استقرار

از پوشه بک‌اند:

```sh
docker compose up -d --build
docker compose logs --tail=100 api market-worker
```

از ریشه سه اپ:

```sh
docker compose -f compose.market.yaml up -d --build customer driver
```

Migration `202611180002_torob_native` ساختار جدید را اضافه می‌کند. قبل از ارتقای دیتابیس موجود بک‌آپ بگیرید. API، PostgreSQL/PostGIS، Redis و Worker با Compose اجرا می‌شوند؛ ساخت دستی دیتابیس لازم نیست. Chromium و فونت فارسی در Dockerfile نصب می‌شوند. نصب محلی Node یا Chrome روی سرور لازم نیست.

تنظیمات بک‌اند:

```dotenv
TOROB_CHROME_PATH=/usr/bin/chromium
TOROB_BROWSER_NO_SANDBOX=true
TOROB_SCAN_TIMEOUT_MS=1800000
TOROB_PRICE_TTL_HOURS=24
TOROB_INITIAL_CATEGORY_URL=https://torob.com/browse/541/باتری-خودرو-battery/
```

Chrome داخل کانتینر محدود Worker اجرا می‌شود؛ این سرویس پورت عمومی ندارد. `TOROB_BROWSER_NO_SANDBOX` برای محیط کانتینری است؛ روی میزبان دارای sandbox قابل استفاده، false بگذارید. مقادیر قدیمی `MARKET_TOROB_*` دیگر استفاده نمی‌شوند. شماره کارت و تنظیمات زرین‌پال با این تغییر دست‌کاری نشده‌اند.

## تنظیم لینک دستی بدون ادمین

تنظیمات منابع اکنون از `.env` خوانده می‌شوند؛ راهنمای فعلی و دستورات دقیق استقرار: [جمعه‌بازار بدون پنل ادمین](ENV-DEPLOYMENT.md).

```dotenv
TOROB_ENABLED=true
TOROB_SOURCES_JSON='[{"name":"باتری خودرو","url":"https://torob.com/browse/541/","category":"batteries","active":true}]'
TOROB_INTERVAL_MINUTES=360
TOROB_MAX_SCROLLS=1000
TOROB_MAX_PRODUCTS=10000
```

فهرست چندمنبعی JSON مرجع تنظیمات است؛ حذف منبع از آن، منبع را غیرفعال می‌کند و داده‌های تاریخی باقی می‌مانند. در نبود JSON، لینک اولیه `TOROB_INITIAL_CATEGORY_URL` استفاده می‌شود. پس از ویرایش env، کانتینر Worker را بازآفرینی کنید؛ دریافت خودکار آغاز می‌شود. cooldown ترب با راه‌اندازی مجدد پاک نمی‌شود. `TOROB_COMPATIBILITY_RULES_JSON` برای قواعد فنی مستند اختیاری است.

مسیر مستقیم `/market` در هر دو اپ مشتری و امدادگر اضافه شده است. مسیر داشبورد `/home` و دکمه‌های موجود نیز حفظ شده‌اند. برای این روش نیازی به انتشار یا ورود پنل ادمین نیست.

## کامل، ناقص و محدودشده

پایان با رسیدن به انتهای صفحه و چند دور نبود لینک جدید تشخیص داده می‌شود. رسیدن به سقف اسکرول، محصول یا زمان، «دریافت کامل» نیست و وضعیت PARTIAL دارد. پیشرفت هر محصول و خطای آن جداگانه ذخیره می‌شود. بعد از پایان cooldown، لینک‌های ذخیره‌شده یک نوبت قطع‌شده می‌توانند در مرحله جزئیات ادامه یابند؛ این نوبت همچنان ناقص گزارش می‌شود. خطای یک محصول، مانع دریافت سایر محصولات همان نوبت نمی‌شود.

محدودیت هر نوبت در پنل قابل تنظیم است. این نسخه ادعای دریافت همه محصولات ترب یا پیمایش نامحدود ندارد؛ اسکرول سایت بیرونی و داده آن ممکن است تغییر کند. لینک‌های ذخیره‌شده در دیتابیس می‌مانند، اما شروع دوباره مرحله اسکرول از ابتدای دسته انجام می‌شود؛ بازیابی مستقیم موقعیت اسکرول مجازی سایت تضمین نشده است.

robots قبل از دریافت بررسی می‌شود. CAPTCHA، منع دسترسی و محدودیت نرخ باعث توقف و cooldown مشترک می‌شوند. تغییر IP، حل CAPTCHA و تغییر هویت برای عبور از محدودیت پیاده نشده‌اند. جزئیات محصول فقط از صفحات `/p/` دریافت می‌شوند؛ لینک خرید فروشگاه‌ها توسط crawler دنبال نمی‌شود.

## مقایسه قیمت و خرید

قیمت هر فروشنده جداست. پیشنهادهای تکراری یک نام فروشگاه در یک محصول، برای مقایسه با ارزان‌ترین پیشنهاد همان نام یکتا می‌شوند؛ این یکتاسازی، تأیید هویت تجاری فروشنده نیست. موجودی فقط طبق مقدار صریح منبع نمایش داده می‌شود. هزینه ارسال نامعلوم به‌عنوان رایگان اعلام نمی‌شود.

دکمه خرید، redirect عمومی خرید ترب برای همان پیشنهاد را باز می‌کند. مرورگر خریدار از ترب به فروشگاه می‌رود؛ خودرو چاره پرداخت فروشگاهی را انجام نمی‌دهد. پارامترهای session و رهگیری مرورگر منبع از لینک ذخیره‌شده حذف می‌شوند؛ انتخابگر پیشنهاد و پارامتر لازم خرید حفظ می‌شود.

قیمت منقضی یا دارای جهش مشکوک در ویترین منتشر نمی‌شود. بخش «قیمت‌های مشکوک» پنل، امکان رفع پرچم پس از بررسی صفحه منبع و ثبت دلیل در audit را دارد؛ قیمت دستی جعل یا جایگزین نمی‌شود. اعتبار پیشنهاد، کمینه TTL سامانه و `priceValidUntil` منبع است. تاریخچه قیمت در دیتابیس ثبت می‌شود؛ روزهای نمودار UTC هستند و اعتبار روزانه قیمت ترب با پایان روز ایران محاسبه می‌شود.

## کاتالوگ خودرو و سازگاری چندخودرویی

کاتالوگ پایه شامل ۱۲۶ ترکیب برند/مدل/تیپ و ۵۳ دسته قطعات است. این عدد، تعداد رکوردهای اولیه است؛ نه ادعای پوشش همه خودروها یا همه تیپ‌ها. بخشی از مدل‌ها با منابع رسمی ایران‌خودرو، کرمان موتور و بروشور پارس‌خودرو بررسی شده‌اند؛ نام‌های متداول باقی‌مانده صرفاً برای جست‌وجوی پایه‌اند و مشخصات مهندسی تأییدنشده برایشان ساخته نشده است. مقدار `sourceUrl` و `catalogCheckedAt` در رکوردها این تفاوت را روشن می‌کند.

اطلاعات «مناسب خودروهای» از مشخصات ساخت‌یافته صفحه ترب استخراج می‌شود. مدل جدید با برند قابل تشخیص به کاتالوگ اضافه می‌شود. این اطلاعات به‌عنوان MODEL_CLAIM، با نشانی و متن منبع، نگهداری می‌شوند؛ قیدهای سال، اتوماتیک و هیبرید حفظ می‌شوند. مثلاً در HTML ارسالی کاربر، شرط «پژو ۲۰۶ از ۱۳۹۶ به بعد» و «کوییک گیربکس اتوماتیک» وجود دارد. این ادعا با سازگاری مهندسیِ مستقل یکی نیست و در اپ برچسب آن نمایش داده می‌شود.

یک قطعه می‌تواند چند رکورد سازگاری داشته باشد؛ جست‌وجوی «باتری ماشین۱» و «باتری ماشین۲» همان محصول مشترک را برمی‌گرداند، اگر هر دو در داده منبع یا قاعده فنی معتبر ثبت شده باشند. موتور، گیربکس و تیپ از نام مشابه خودرو استنتاج نمی‌شوند. سال شمسی با شمسی و سال میلادی با میلادی مقایسه می‌شود؛ تبدیل حدسی سال مدل انجام نمی‌شود.

قواعد فنی در پنل بخش «قواعد سازگاری» ثبت می‌شوند. برای باتری، یکسان‌بودن آمپرساعت کافی نیست؛ تطبیق قطعی قاعده به ظرفیت، ولتاژ، قالب، قطب، فناوری، طول، عرض و ارتفاع نیاز دارد. مشخصات متناقض یا ناقص، قاعده قطعی را فعال نمی‌کنند. قاعده باید مرجع، تاریخ بررسی، تاریخ اعتبار و کلید خودروهای هدف داشته باشد؛ موارد verified=false در تطبیق قطعی استفاده نمی‌شوند. اطلاعاتی مثل ابعاد سه‌تایی بدون ترتیب صریح، به‌صورت حدسی به طول/عرض/ارتفاع تبدیل نمی‌شوند.

برای دیگر قطعات نیز قاعده مستند می‌تواند برند، کد فنی یا OEM و مشخصات را به چند خودرو وصل کند. قواعد پس از دریافت بعدی محصول اعمال می‌شوند. اطلاعات سازگاری کامل و همواره به‌روز برای همه خودروها بدون کاتالوگ مرجع معتبر قابل تضمین نیست؛ این نسخه چنین داده‌ای را جعل نمی‌کند.

منابع بررسی کاتالوگ: [محصولات ایران‌خودرو](https://www.ikco.ir/fa/)، [مشخصات تارا](https://www.ikco.ir/fa/Product.aspx?ID=321&Section=2)، [محصولات کرمان موتور](https://www.kermanmotor.com/products)، [بروشور کوییک R](https://pkhauto.com/uploads/cars/quik_R_cvt_14010425_compressed.pdf). این لینک‌ها منبع پژوهش کاتالوگ‌اند؛ crawler قیمت فقط ترب را می‌خواند.

## ابزار مستقل برای بررسی

داخل کانتینر Worker:

```sh
node scripts/torob-crawl.js collect 'https://torob.com/browse/541/' --max-scrolls=1000 --max-products=10000 --output=links.json
node scripts/torob-crawl.js product 'https://torob.com/p/c2a29e6f-b706-4695-ba9c-13767a09e807/' --output=product.json
```

`--standalone` برای آزمون کوچک بدون Redis است؛ در اجرای معمول از Redis استفاده کنید تا محدودیت مشترک رعایت شود. فایل خروجی موجود بازنویسی نمی‌شود. `collect` فقط لینک و وضعیت پایان را می‌دهد و `product` فقط داده صفحه را استخراج می‌کند؛ ثبت پایدار و صف‌بندی تولید توسط Worker اصلی انجام می‌شود.

## تست

آزمون‌های منطق استخراج روی نسخه کوچک و پاک‌سازی‌شده HTML ارسالی کاربر اجرا می‌شوند؛ هیچ قیمت نمونه در تولید seed نمی‌شود. تست HTTP، سازگاری مشترک، محدودیت سال/گیربکس، واحد پول، یکتاسازی فروشنده و توقف مرورگر در خطا وجود دارد.

```sh
docker build --target test -t khodrochare-unit .
docker compose -p khodrochare-test -f compose.yaml -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from api
```

تست مرورگر و build اپ‌ها از ریشه پروژه با `Dockerfile.e2e` اجرا می‌شوند. وجود فایل تست به معنی اجرای آن نیست. شواهد اجرای فعلی و محدودیت‌ها: [VALIDATION.md](VALIDATION.md).
