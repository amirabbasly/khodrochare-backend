# خودروها، تیکت و یادآور سرویس

## راه‌اندازی

frontend مشتری، پنل مدیریت و backend باید با هم منتشر شوند. پیش از راه‌اندازی API:

```
npm run db:migrate
npm run prisma:generate
```

دو migration جدید: `202611190003_vehicle_names` و `202611190004_customer_care`. داده‌ها به حساب و خودروی واقعی متصل‌اند؛ اطلاعات سرویس یا تیکت در localStorage ذخیره نمی‌شود.

## کاتالوگ خودرو

۴۶۱ ردیف نام در `src/vehicle-catalog.js` به کاتالوگ موجود افزوده/ادغام می‌شود؛ شامل لوکانو L5/L7/L8، خودروهای داخلی، مونتاژی و وارداتی. این یک فهرست نام توسعه‌پذیر است، نه ادعای پوشش تمام مدل‌ها/تیپ‌های جهان یا مشخصات فنی آن‌ها. تیپ تأییدنشده «نامشخص» می‌ماند. aliases برند و مدل فارسی/لاتین برای جستجو استفاده می‌شوند؛ نام برند به‌تنهایی به‌عنوان alias سازگاری قطعه وارد نمی‌شود. bootstrap جمعه‌بازار نیز نام‌های جدید و قدیمی را با حفظ نام‌های جایگزین ادغام می‌کند. بررسی سازگاری seed: `node scripts/generate-vehicle-names.js --check`. گزینه `--author` فقط پیش از اولین استقرار همین migration کاربرد دارد.

## یادآور

`GET/POST /garage` خودروهای مالک را می‌خواند/اضافه می‌کند؛ فیلدهای جدید شامل catalogCarId، productionYear، mileage هستند. خودروهای قبلی `/me/vehicles` هم نمایش داده می‌شوند. مالک می‌تواند مدل خودروی قبلی را تکمیل و کیلومتر را با `PATCH /garage/:id` افزایش دهد. کاهش کیلومتر و دسترسی به خودروی دیگری رد می‌شود.

`GET/POST /garage/:id/services` آخرین سابقه هر سرویس و برنامه محاسبه‌شده را برمی‌گرداند/ثبت می‌کند. ۱۵ عنوان در چهار دسته روغن و مایعات، فیلترها، تسمه و جرقه، بازدید و ایمنی وجود دارد. آخرین سابقه بر اساس بیشترین کیلومتر و سپس تاریخ انتخاب می‌شود. کیلومتر سرویس از کیلومتر فعلی بیشتر و تاریخ آن از امروز جلوتر نیست. موعد: کیلومتر آخر + فاصله کیلومتری؛ تاریخ آخر + فاصله ماهانه با رعایت انتهای ماه. هرکدام زودتر برسد اولویت دارد. سررسیدگذشته و نزدیک به سررسید در ابتدا قرار می‌گیرند. این نسخه محاسبه و نمایش داخل برنامه دارد؛ ارسال push/SMS یادآور پیاده‌سازی نشده است.

بازه‌های قابل استناد فعلی برای پژو ۲۰۷ از دفترچه سازنده (نسخه میزبانی‌شده در [پدیده خودرو](https://padidehkhodro.com/wp-content/uploads/2024/04/Peugeot-207i-car-manual.pdf#page=155)) استخراج شده: روغن موتور/فیلتر روغن ۱۰۰۰۰ کیلومتر یا ۱۲ ماه، روغن ترمز ۴۰۰۰۰ یا ۲۴ ماه، تسمه تایم/دینام ۸۰۰۰۰ یا ۳۶ ماه، بازدید ترمز/تایر ۱۰۰۰۰ یا ۱۲ ماه. متن منبع و نیاز به تطبیق سال/موتور در رابط نمایش داده می‌شود. برای مدل‌ها و سرویس‌های فاقد بازه تأییدشده، سیستم عدد حدسی نمی‌سازد: مالک فاصله را از دفترچه/کارشناس ثبت می‌کند و محاسبه از آن به بعد خودکار است. شرایط سخت و بازه‌های سفارشی قابل ورودند. برای افزودن بازه مدل‌های دیگر، `intervalFor` باید با مستندات همان موتور و سال توسعه یابد.

## پشتیبانی

`GET /support/departments`، `GET/POST /support/tickets`، `GET/PATCH /support/tickets/:id` و `POST /support/tickets/:id/messages` مسیرهای خصوصی کاربرند. شش دپارتمان فنی، امداد، تالار، جمعه‌بازار، مالی و عمومی هستند. تیکت OPEN، WAITING_CUSTOMER یا CLOSED است. تیکت بسته پیام جدید نمی‌پذیرد؛ مالک/کارشناس می‌توانند آن را باز کنند. API ثبت تیکت ۱۰ مورد در ساعت و پیام ۶۰ در دقیقه محدود می‌شود. پیام‌ها متن ساده‌اند و React آن‌ها را escape می‌کند.

مسیرهای `/admin/support/tickets` با نشست ادمین موجود محافظت می‌شوند؛ صفحه `/support` در پنل، فیلتر دپارتمان/وضعیت، پاسخ و بستن/بازکردن تیکت دارد. چت تیکت با polling پنج‌ثانیه‌ای هنگام دیده‌شدن صفحه تازه می‌شود. تاریخچه صفحه‌بندی‌شده ۱۰۰ پیام با cursor شناسه پیام است تا پیام‌های هم‌زمان جا نیفتند. شماره ارتباط کارشناس: 02182801043.

## اعتبارسنجی

`npm test` در backend و `node --test test/customer-care.test.js` شامل تست واقعی Prisma/HTTP روی PGlite با SQL دقیق migrationها هستند. سناریوها: جستجوی فارسی/لاتین/بدون فاصله لوکانو، حفظ مالکیت، سابقه و محاسبه موعد، تیکت و پاسخ ادمین، بسته/بازشدن، cursor با timestamp یکسان، و عدم ساخت سازگاری قطعه از نام برند تنها. اپ: build، lint و `playwright.care.config.ts` (۱۲ سناریو). پنل پاسخگویی: `playwright.support-admin.config.ts` در مخزن اپ با سرور پنل روی 3321. تست‌های مرورگر API را mock می‌کنند؛ جایگزین بررسی پس از استقرار روی PostgreSQL/Redis واقعی نیستند.
