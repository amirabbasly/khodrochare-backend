# آدرس، کاتالوگ خودرو و پرداخت کارت‌به‌کارت

## استقرار

ابتدا بک‌اند و سپس هر دو اپ را به‌روزرسانی کنید. در پوشه بک‌اند:

```sh
docker compose up -d --build
```

فرمان شروع کانتینر، migration افزایشی `202610200002_catalog_addresses_payments` را اجرا می‌کند. شش گروه تعرفه و ۱۱۳ رکورد نام خودرو/نام جایگزین خودکار درج می‌شوند؛ ساخت دستی دیتابیس یا اجرای seed جدا لازم نیست. نرخ‌ها برای درخواست‌های جدید از `TariffGroup` و مدل از `VehicleModel` خوانده می‌شوند؛ snapshot درخواست‌های قبلی تغییر نمی‌کند. نام‌های ناشناخته باید از نتایج جست‌وجو انتخاب شوند؛ «سایر خودروها» گروه توافقی است.

`PHOTON_URL` در `.env.example` اضافه شده و پیش‌فرض آن `https://photon.komoot.io` است؛ نبود این متغیر در `.env` قبلی مانع شروع سرویس نیست. برای ترافیک تولید می‌توان نشانی نمونه اختصاصی Photon را تنظیم کرد. نمونه عمومی برای استفاده متوسط است و تضمین دسترس‌پذیری ندارد: [مستندات رسمی Photon](https://github.com/komoot/photon)، [API جست‌وجو](https://github.com/komoot/photon/blob/master/docs/api-v1.md).

## آدرس و برآورد

- `GET /api/v1/locations/search?q=تهران ولیعصر`: جست‌وجوی خیابان در ایران؛ نتیجه شامل `id`، `label`، `city`، `street` و مختصات داخلی است. رابط فقط شهر و خیابان را نمایش می‌دهد. انتخاب آدرس یک ساعت معتبر است؛ در صورت انقضا دوباره جست‌وجو شود.
- `GET /api/v1/vehicle-models?q=۲۰۶`: جست‌وجوی نام و نام‌های جایگزین با یکسان‌سازی حروف و ارقام فارسی/عربی/لاتین؛ پاسخ شامل مدل و گروه تعرفه است.
- `POST /api/v1/requests/towing/estimate`: همان بدنه ثبت حمل شامل `vehicleModelId`، `vehicleName`، `vehiclePlate`، `origin`، `destination`، `originPlaceId`، `destinationPlaceId` و شرایط حمل؛ برآورد سرور را بدون ثبت درخواست برمی‌گرداند. شناسه‌های آدرس، مختصات معتبر سمت سرور را تعیین می‌کنند.
- `POST /api/v1/requests/towing`: قیمت و مسافت در زمان ثبت دوباره در سرور محاسبه و همراه نام آدرس‌ها و مدل ذخیره می‌شوند. قیمت ارسال‌شده توسط کلاینت پذیرفته نمی‌شود. روش مسافت همچنان تابع `DISTANCE_MODE` است؛ `geodesic` فاصله مستقیم و `road` مسیر OSRM است.

## قطعات و کمیسیون

ورودی تعمیر در محل ۸۰۰٬۰۰۰ تومان است. امدادگر تخصیص‌یافته پس از رسیدن، هزینه قطعات را اعلام می‌کند؛ اگر قطعه لازم نیست مقدار **صفر** را ثبت می‌کند. مشتری باید همان نسخه پیشنهاد را تأیید کند. اصلاح پیشنهاد، تأیید قبلی را لغو می‌کند. پس از ایجاد پرداخت، مبلغ قفل می‌شود.

- امداد: `کمیسیون = round((خدمت + قطعات تأییدشده) × ۳۰٪)`.
- حمل: `کمیسیون = round((خدمت + قطعات تأییدشده) × ۲۰٪)`؛ در ماژول فعلی حمل قطعاتی ثبت نمی‌شود.
- سهم امدادگر = مجموع منهای کمیسیون. همه مبالغ **تومان** هستند. برای مثال ۸۰۰٬۰۰۰ خدمت + ۲۰۰٬۰۰۰ قطعات: قابل واریز ۱٬۰۰۰٬۰۰۰، کمیسیون ۳۰۰٬۰۰۰، سهم امدادگر ۷۰۰٬۰۰۰.
- حمل توافقی تا تعیین مبلغ نهایی امکان ایجاد پرداخت ندارد؛ تعیین مبلغ توافقی و بازپرداخت هنوز پیاده نشده است.

مسیرها:

| مسیر | نقش و کاربرد |
| --- | --- |
| `POST /requests/:id/parts-quote` | امدادگر همان درخواست؛ `{ "amountToman": 200000 }` |
| `POST /requests/:id/parts-quote/approve` | مشتری مالک؛ `{ "version": 1 }` |
| `POST /requests/:id/payment` | مشتری مالک؛ ایجاد یا دریافت پرداخت قبلی |
| `GET /requests/:id/payment` | مشتری مالک یا امدادگر تخصیص‌یافته؛ مشاهده وضعیت |
| `POST /requests/:id/payment/report` | مشتری مالک؛ `{ "bankReference": "123456789", "transferredAt": "2026-10-20T10:00:00.000Z" }` |
| `GET /drivers/earnings` | مجموع سهم‌های ثبت‌شده و ۵۰ ردیف آخر امدادگر |

همه مسیرهای جدول پیشوند `/api/v1` و احراز هویت دارند.

## بررسی واریز توسط مسئول حساب

شماره کارت: **6219861435789192** — **حساب خودرو چاره**. اپ مبلغ کامل را نمایش می‌دهد؛ مشتری شماره پیگیری و زمان واریز را ثبت می‌کند. وضعیت `SUBMITTED` به معنی تأیید بانک نیست. شماره پیگیری تکراری پذیرفته نمی‌شود. بررسی فعلاً با ابزار سرور انجام می‌شود و پنل مدیریتی در این تغییر ساخته نشده است.

ابتدا فهرست واریزهای اعلام‌شده را بخوانید:

```sh
docker compose exec api node scripts/list-payments.js
```

پس از تطبیق واقعی مبلغ، شماره پیگیری و زمان با گردش حساب، شناسه پرداخت خروجی را بررسی کنید:

```sh
docker compose exec api node scripts/review-payment.js PAYMENT_ID approve OPERATOR_NAME "Matched bank statement"
# برای رد و ثبت دلیل:
docker compose exec api node scripts/review-payment.js PAYMENT_ID reject OPERATOR_NAME "Transfer not found"
```

این دستورات نیازمند دسترسی سرور/دیتابیس‌اند؛ API عمومی تأیید پرداخت وجود ندارد. نام مسئول، زمان و دلیل بررسی نگهداری می‌شود. پس از تأیید واریز **و** تکمیل خدمت، سهم امدادگر دقیقاً یک‌بار در دفتر درآمد ثبت می‌شود؛ این ثبت، انتقال بانکی خودکار به امدادگر نیست. لغو درخواست با واریز اعلام‌شده/تأییدشده مسدود است و به بررسی پشتیبانی نیاز دارد.

## اعتبارسنجی

۳۴ تست بک‌اند، اعتبارسنجی و تولید Prisma، build و lint هر دو اپ و ۱۷ سناریوی مرورگر موفق شدند (۱۶ سناریو در اجرای کامل و سپس تست جدید تاریخچه و دو سناریوی مرتبط پس از اصلاح نهایی). تست مرورگر پاسخ‌های API را mock می‌کند. جست‌وجوی واقعی Photon با آدرس عمومی تهران پاسخ معتبر داد. Docker در این محیط نصب نیست؛ اجرای migration، تست یکپارچه PostgreSQL/PostGIS/Redis و دیپلوی واقعی انجام نشده‌اند. تست یکپارچه برای آدرس‌های کش‌شده، تأیید قطعات، اعلام واریز و سهم امدادگر به‌روزرسانی شده است.
