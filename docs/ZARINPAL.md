# پرداخت زرین‌پال و کیف پول

به‌روزرسانی: ۱۸ نوامبر ۲۰۲۶.

شماره کارت و فرم اعلام واریز از اپ مشتری حذف شده‌اند؛ شارژ کیف پول هر دو اپ و پرداخت درخواست خدمت به زرین‌پال متصل هستند. مسیر عمومی ثبت کارت‌به‌کارت پاسخ 410 می‌دهد. ستون‌ها و ابزار بررسی قدیمی فقط برای حفظ سابقه پرداخت‌های قبلی نگهداری می‌شوند و به کلاینت نمایش داده نمی‌شوند.

## حالت فعلی: sandbox رسمی

حالت پیش‌فرض، آزمایشی است و کلید واقعی لازم ندارد. شناسه UUID آزمایشی طبق مستندات رسمی استفاده می‌شود. مبالغ در اپ تومان هستند و برای request و verify دقیقاً در ۱۰ ضرب و با واحد IRR به درگاه ارسال می‌شوند.

در `.env` بک‌اند:

```dotenv
ZARINPAL_MODE=sandbox
ZARINPAL_MERCHANT_ID=
PAYMENT_CALLBACK_URL=https://api.khodrochare.ir/api/v1/payments/zarinpal/callback
CUSTOMER_APP_URL=https://app.khodrochare.ir
DRIVER_APP_URL=https://driver.khodrochare.ir
```

اگر دامنه اپ‌ها متفاوت است، دو مقدار آخر را اصلاح کنید. این دو مقدار نشانی وب خود اپ‌ها هستند، نه API. پس از پرداخت، کاربر به `/payment/return` همان اپ می‌رود. callback باید از اینترنت با HTTPS در دسترس باشد. هیچ کلید درگاه در متغیرهای `NEXT_PUBLIC_*` یا کد کلاینت قرار ندهید.

از پوشه بک‌اند:

```sh
docker compose up -d --build
docker compose logs --tail=100 api
```

از ریشه سه اپ:

```sh
docker compose -f compose.market.yaml up -d --build
```

Migration `202611180001_zarinpal` هنگام شروع API، جداول تراکنش درگاه و دفتر کیف پول را اضافه و وضعیت‌های جدید پرداخت را مجاز می‌کند. قبل از ارتقای دیتابیس موجود، بک‌آپ تهیه کنید. اطلاعات بانکی تاریخی حذف نمی‌شوند؛ شماره کارت از پاسخ پرداخت و UI حذف شده است.

## آزمایش در اپ

۱. وارد اپ مشتری یا امدادگر شوید و «کیف پول» را باز کنید.

۲. مبلغی بین ۱۰ هزار و ۱۰۰ میلیون تومان وارد کنید. دکمه «ورود به درگاه آزمایشی زرین‌پال» یک Authority واقعی sandbox ایجاد و کاربر را به `sandbox.zarinpal.com/pg/StartPay/...` منتقل می‌کند.

۳. پرداخت آزمایشی را در خود sandbox کامل یا لغو کنید. اطلاعات کارت واقعی در اپ خودرو چاره دریافت نمی‌شود.

۴. نتیجه پس از verify سرور نمایش داده می‌شود. موجودی آزمایشی کیف پول جدا از موجودی واقعی نگهداری می‌شود؛ به درآمد واقعی امدادگر یا اپ اضافه نمی‌شود.

۵. برای پرداخت خدمت، ابتدا مبلغ نهایی خدمت و هزینه قطعات تأییدشده باید موجود باشد. دکمه پرداخت، مجموع همین مبالغ سرور را به درگاه می‌برد. سهم اپلیکیشن همچنان برای امداد ۳۰٪ و حمل ۲۰٪ از مجموع خدمت و قطعات است.

شارژ کیف پول و پرداخت خدمت مسیرهای مستقل‌اند؛ کسر خودکار مبلغ خدمت از موجودی کیف پول یا برداشت وجه در این تغییر اضافه نشده است. درآمد ثبت‌شده امدادگر نیز دفتر جداگانه‌ای دارد و با شارژ کیف پول یکی نیست.

## فعال‌کردن درگاه واقعی

پس از دریافت مرچنت معتبر، فقط در `.env` امن بک‌اند تنظیم کنید:

```dotenv
ZARINPAL_MODE=live
ZARINPAL_MERCHANT_ID=YOUR_REAL_MERCHANT_UUID
```

پرداخت‌های آزمایشی باز را پیش از تغییر حالت تکمیل یا لغو کنید. سپس:

```sh
docker compose up -d --force-recreate api
```

بازسازی اپ‌ها برای تغییر کلید یا حالت لازم نیست. مرچنت خالی یا نامعتبر در حالت live با خطای تنظیمات مواجه می‌شود؛ به‌صورت پنهانی به پرداخت آزمایشی برنمی‌گردد. دامنه callback و الزامات پذیرندگی باید با تنظیمات پنل زرین‌پال هماهنگ باشند.

## تأیید و جلوگیری از ثبت تکراری

- مبلغ، مالک پرداخت، حالت sandbox/live و Authority در سرور ذخیره می‌شوند. مرورگر نمی‌تواند مبلغ درخواست خدمت را تعیین کند.
- پارامتر `Status=OK` به‌تنهایی تأیید پرداخت نیست؛ سرور verify می‌کند. کدهای موفق 100 و 101 پشتیبانی می‌شوند.
- کلید idempotency در شروع، Authority یکتا، قفل ردیف هنگام تأیید و ورودی یکتای کیف پول، جلوی دوباره شارژشدن یک تراکنش را می‌گیرند.
- callback لغوشده پولی اضافه نمی‌کند. اگر تأیید سرور با timeout مواجه شود، صفحه نتیجه دکمه بررسی دوباره دارد؛ تا تأیید قطعی هیچ مبلغی اضافه نمی‌شود.
- پرداخت تکراری یک خدمت یا پرداخت برای درخواست لغوشده، به وضعیت پیگیری بازگشت وجه می‌رود؛ بازپرداخت خودکار در این نسخه انجام نمی‌شود.
- پرداخت خدمت آزمایشی وضعیت `SANDBOX_VERIFIED` دارد؛ تنها `VERIFIED` واقعی همراه با تکمیل خدمت وارد درآمد امدادگر می‌شود.

## API

| مسیر | کارکرد |
| --- | --- |
| GET /api/v1/wallet | موجودی واقعی و آزمایشی و آخرین ۵۰ شارژ تأییدشده، فقط حساب خود کاربر |
| POST /api/v1/wallet/topups | amountToman و idempotencyKey، مشتری و امدادگر |
| POST /api/v1/requests/:id/payment/checkout | idempotencyKey، فقط مشتری مالک درخواست |
| GET /api/v1/payments/checkouts/:id | وضعیت پرداخت، فقط مالک |
| POST /api/v1/payments/checkouts/:id/verify | بررسی مجدد با مبلغ ذخیره‌شده، فقط مالک |
| GET /api/v1/payments/zarinpal/callback | بازگشت زرین‌پال و verify سمت سرور |

## شواهد تست

درخواست واقعی ساخت پرداخت در sandbox در ۱۸ نوامبر موفق شد؛ Authority با پیشوند S و طول ۳۶ و لینک دامنه sandbox دریافت شد. هیچ پرداخت واقعی انجام نشد. تأیید، لغو، callback، idempotency و تفکیک موجودی در تست‌های خودکار با پاسخ کنترل‌شده درگاه بررسی می‌شوند. تست کامل مرورگر و اجرای migration روی دیتابیس واقعی، به میزبان Docker نیاز دارد و در محیط توسعه فعلی اجرا نشده است.

مراجع رسمی: [راهنمای اتصال](https://www.zarinpal.com/docs/paymentGateway/connectToGateway)، [sandbox](https://www.zarinpal.com/docs/paymentGateway/sandBox)، [واحد پول](https://www.zarinpal.com/docs/paymentGateway/moreFeatures/currency).


اعتبارسنجی همین نسخه: ۷۱ تست واحد/قرارداد بک‌اند موفق؛ lint و TypeScript هر سه اپ و Prisma validate موفق. تست‌های مرورگر مربوط به پرداخت و کیف پول به جریان sandbox تغییر کرده‌اند، ولی اجرای آن‌ها در Docker هنوز انجام نشده است.
